# KRAVV-IENT V3 — Core Analysis Workflow PoC

Completed 14 September 2026. This phase extends the existing V3 implementation and stops at the core analysis workflow.

1. **Core workflow changes.** Lightweight case intake now explains that creation opens a workspace; context editing explains ongoing enrichment. Overview and Evidence connect source documents, manual evidence, readiness and analysis. Saved results lead to explicit diligence creation, human review, recommendation and decision. Tabs remain freely navigable.

2. **Analysis states implemented.** Readiness shows actual source/evidence/status counts and the existing analysis contexts, including an honest zero-evidence state. Processing displays five restrained stages over approximately three seconds. The result shows run identity/time/context, snapshot evidence and referenced-document counts, executive synthesis, expandable saved findings, source inspection, supportive evidence, saved counterarguments, conflicts, unknowns, diligence suggestions and run-specific human review. Older runs remain selectable; latest is marked.

3. **Simulated logic used.** The existing rules-v1 engine and saved findings were not changed. The new presentation groups Supported/Verified, Reported, Conflicting and Unknown entries and derives simple questions from their recorded status. No scores, inferred materiality, automatic contradiction reconciliation or priority ranking are introduced. Current-versus-snapshot evidence differences compare stable IDs and persisted fields. Document additions since a run are not inferred because the run does not contain a full document snapshot.

4. **Visual and interaction changes.** The existing graphite/blue V3 shell, bottom global navigation and case tabs remain. Readiness, processing and results have distinct surfaces. Findings use progressive disclosure. Next-step cues remain contextual rather than a mandatory wizard. The PoC remains desktop-only; existing basic narrow-viewport protection and reduced-motion rules are retained.

5. **Existing business logic preserved.** No changes to the model, API action contracts, D1/R2 storage, authentication, optimistic revision checks, role gates, lifecycle, evidence history, analysis snapshots, judgment history or portfolio logic. Suggested diligence opens the existing editable form; only saving creates a record. Human disagreement appends a review without replacing the assessment. Original portfolio-linked cases and their investment/decision histories remain present and unchanged.

6. **What remains simulated.** Interpretation, synthesis framing and suggested follow-up wording are deterministic PoC behavior. Processing stages are an illustration, not server telemetry. The save starts immediately and a successful result appears only after the save confirms; the animation itself is not a persisted background job. Evidence statuses are recorded by humans, not independently verified. Local identity/role switching remains the existing prototype behavior.

7. **Intentionally unimplemented.** No real AI API was implemented. No chatbot/assistant was implemented. No automatic extraction, external research, embeddings, RAG, model routing, multi-agent intelligence, financial scoring or autonomous decision making was added. Advanced version comparison, document-delta history and durable background-job orchestration are outside this phase. The hosted Sites deployment was not updated; this phase is delivered as local implementation and GitHub source.

8. **Assumptions and unresolved product questions.** The existing question model has no run foreign key. Suggested question text includes the originating run ID/context and evidence snapshot, while the evidence trigger points to the current entry. This editable text is not immutable provenance; a formal relationship remains a product decision. Supported/Verified entries are shown as a stronger factual basis, not proof of thesis fit or future success. Critical-unknown materiality and diligence prioritization remain human judgments. Existing provisional lifecycle, firm-role administration, IC governance and behavior after an invested case receives a later outcome remain unresolved. Answered diligence remains open until Resolved under the existing rule. No rule was changed silently. The exact numbered project-document set was not present in the repository; previously supplied domain/vision/PRD/brief materials and existing implementation were used. Existing sample records, including Aster Robotics, were not replaced; a separate fictional validation case illustrates the richer mixed-status workflow.
